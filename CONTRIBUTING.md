# Contributing

## Development setup

- Linux x86_64 is the supported development platform (see
  `docs/adr/0001-platform-baseline.md`).
- Install rustup; `rust-toolchain.toml` pins Rust 1.99.1
  automatically.
- Install Node 24 and enable pnpm 12 (`corepack` or your package
  manager); `packageManager` pins `pnpm@12.10.1`.
- `pnpm install` then `cargo test --workspace` (should be green before
  you start).

## House rules

1. **Failing behavioral test first** for any security, parsing,
   persistence, or sync change. Write the test that demonstrates the
   bug or the new behavior, watch it fail, then fix the
   implementation. Refactors without behavior change do not need a new
   test, but the suite must stay green.
2. **Synthetic OTP fixtures only.** Test data must be generated or
   taken from public RFC vectors (`tests/fixtures/`). Never commit
   personal secrets, real accounts, or screenshots containing real
   codes.
3. **Coherent commits.** One logical change per commit; the message
   says what and why. Do not mix a security fix with an unrelated
   refactor.
4. Before submitting, run and pass all of:
   ```
   cargo fmt
   cargo clippy --workspace --all-targets
   cargo test --workspace
   pnpm -r check        # typecheck + contract drift
   ```
5. **Architecture changes need an ADR** in `docs/adr/` (numbered,
   dated, with status). If you are changing the vault format, the sync
   protocol, or a client boundary, the ADR comes first.
6. **Security-sensitive changes** (crypto, key handling, Tauri
   capabilities, the sync protocol) require maintainer review before
   merge; a regular approval is not sufficient.

## Contract DTOs

`packages/contracts/src/generated/` is generated by ts-rs. Never edit
it by hand; regenerate with:

```
cargo test -p clavis-core dto::export
```

`pnpm -r check` fails if the generated files drift from Rust.

## Fuzzing

`fuzz/fuzz_targets/` contains cargo-fuzz targets. They require
cargo-fuzz nightly tooling and are not part of normal CI; see
`fuzz/README.md`.
